# Bounded negative ZIP lookup cache

Local-only implementation: `client/resources/ZipEntryMissCache.java` and `client/mixin/ZipEntryMissCacheMixin.java`. Parent owns startup-only default-off plugin registration, safe-mode veto, exclusions (`packforge`, `quick-pack`) and central build.

Native26.3 FilePackResources private getResource(String) first obtains the current SharedZipFileAccess handle, returns null if none, invokes ZipFile.getEntry on addPrefix(path), returns null on miss, otherwise creates the unmodified native IoSupplier. See `work/pack-resource-path-native-javap.txt`. The new redirect changes only that exact getEntry call. The cache sees the fully prefixed lookup string, so pack overlays and native root paths remain distinct. Enumeration, entry metadata, duplicate-name ordering, resource callbacks, positive ZipEntry instances, suppliers and stream lifetimes are unchanged.

Admission: only exact java.util.zip.ZipFile runtime class, nonnull path length<=1024. Unknown subclasses/null inputs/overlong names invoke the original virtual Java method once and retain its errors. Null results alone are recorded. Each FilePackResources instance retains at most128 path keys (FIFO one-key eviction under pressure, no full-map churn) and a weak handle reference. Native ZipFile central-directory contents are stable during a handle's lifetime; an external archive reopen yields a different handle and clears keys. FilePackResources.close HEAD clears the cache before native close. A matching cache hit calls ZipFile.size first to reject a closed handle. No cache monitor is held during a miss's virtual method; generation and weak identity rechecked on publication prevent a reentrant close/reset or another handle from publishing stale misses. Concurrent close races obey the native open-handle linearization boundary; the cache does not keep a resource open.

Root explicitly permitted typed @Redirect rather than WrapOperation because Operation.call adds an Object[] on positive/uncached lookups. This means another mod intercepting that same invocation is an integration boundary; known competing pack optimizers are excluded and unknown hook compatibility is not guaranteed. Repeated-negative hits intentionally skip getEntry invocation. The flag must remain opt-in. No safe fallback can preserve arbitrary callbacks while also skipping their work.

Expected benefit is avoiding repeated Java ZIP name encoding/central-directory lookup for missing resources/metadata. Hash lookup, synchronization and bounded key storage add overhead; no measured performance or FPS gain is claimed. A prefix-index alternative was rejected for this change because full entry snapshot/class/duplicate metadata and callback-enumeration contracts required substantially more proof. No third-party implementation was copied.

No game, runtime or unit tests executed. Parent performs compilation/package verification. Deployed Java25 bytecode is saved in `work/zip-miss-jdk25-javap.txt`: getEntry first rejects null name; size and getEntry both synchronize on the ZipFile monitor and call identical ensureOpen, including closed/uninitialized error messages. All cache bookkeeping is synchronized. Native miss execution releases the ZIP monitor before cache publication; closeHEAD releases the cache monitor before calling native ZIP close. A cache-hit size check cannot acquire the cache monitor in reverse from native Java code. Unknown external synchronization/instrumentation is outside the native contract.
