# Local dev.5 integration

No Minecraft, runtime or unit tests; compilation and archive checks only. No performance measurements. Original repository remains read-only.

- FBO lookup probe: reviewed native CacheKey numeric packing/hash/equality and association ownership. The probe is private, never inserted or used to create a framebuffer; original misses still create native keys/FBOs. Bounded primitive arrays. CacheKey data/hash lose final metadata but only the marked private probe is mutated. The cancellable injection and boxed return can still allocate; the whole hook is not allocation-free. Both key/cache mixins share one startup gate, checked without loading the helper from the plugin.
- ZIP misses: bounded 128 negative keys per FilePackResources, at most 1024 UTF16 code units per key, weak exact ZipFile identity. Miss lookup occurs outside bookkeeping lock; closure/reopen invalidates. Cached misses still run size() to preserve native closed-handle rejection. Positive entries and streams are never cached. A typed Redirect avoids a varargs bridge but remains incompatible with unknown competing getEntry interception; known pack optimizers excluded.
- Texture references: native getMaterial runs isTextureReference first, retaining ModernFix's guard. Native exact Object2ObjectArrayMap scans keys backwards with Objects.equals. Helper compares String suffix bytes semantically using case-sensitive regionMatches without substring allocation; missing/nonstandard layout, custom map, raw custom key or non-null default value uses native substring/get. Read-only VarHandles resolve lazily once. No library mixin or global material cache. Native constructor/resolver and fastutil bytecode saved in texture-slots-*-javap.txt. Pinned catalog's only TextureSlots overlap is ModernFix's isTextureReference injection, which remains invoked.
- Maximum profile container distance: optional 32-block chest/shulker rendering cap, after original native visibility result. Exact native entity AND renderer classes only; offscreen route, custom renderers, other entities, nonfinite camera and non-Maximum profiles bypass. It skips extraction/render submission only, never tick/update logic. Intentional visible-distance tradeoff, not unchanged-visual optimization. Exact target is tryExtractRenderState, not extractRenderState; review corrected this before release.

All four feature groups remain off unless their startup property is explicitly set. No 3x or other FPS claim.
