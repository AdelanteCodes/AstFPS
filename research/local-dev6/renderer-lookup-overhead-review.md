# Renderer lookup decision

Keep RendererTypeLookupCache explicit opt-in/off by default. Do not claim a speedup or include it as an established performance win. One cache hit avoids a small native Guava key hash/probe/equals lookup, while adding WrapOperation handler dispatch, gate checks, client/main-thread checks, reentrancy/map/type checks and a counter. Misses add Operation.call Object[2] varargs/bridge work (subject to JIT elimination). Singleentry hit rate depends ordering. This can be neutral or slower. No runtime evidence available or requested; no tests/game/benchmark run.

Native map identity and reload invalidation handle replacement. Mutable/custommap delegation handles dynamicregistration, avataroverloads remain original. BadOptimizations/rendererreplace conflicts bypass. Unknown modifications to same native Map.get callsite can supply dynamic results/side effects; immutable underlying map does not prove wrapper purity. Current startupflag must remain exploratory, not universal-compatible/defaultenabled.

Next highest-leverage native CPU candidate: exact100-entry FIFO position-cache bookkeeping in BlockModelLighter.Cache, reused by Indigo AO. Native code does multiple light/shade lookups perquad and uses Long2IntLinkedOpenHashMap/Long2FloatLinkedOpenHashMap with100-entry FIFOeviction. A bounded direct-index lookup structure that preserves EXACT eviction, NaN/missingvalue behavior, reset and callback invocation sequence could avoid hash/linkedbookkeeping without touching vertex data/AO arithmetic. This requires a focused proof of100-entry FIFO semantics, repeated NaN shade values, enabled/disabled switching, reentrancy and outofregion positions before code. It is a candidate, not promised improvement.

Crucial rejectedshortcut: RenderSectionRegion retains a LIVE LevelLightEngine; region blockstates are copied but lighting is not proven snapshotted. Increasing cache capacity or retaining an entire section's lightvalues could change freshness/callback behavior. No whole-section lightingmemo should be implemented under assumed immutablelighting. NativeBLOCK vertex writer already directly writes nativefloat attributes; replacementwriter/quantization/batchedpointerreservation were rejected earlier.
